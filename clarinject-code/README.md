# ClarInject-Code

**Measuring and Mitigating the Security Cost of Clarification in LLM Coding Agents**

This repository contains the benchmark, evaluation harness, and analysis code for the paper:

> **The Clarification Tax: Measuring and Mitigating the Safety Cost of Collaborative Coding Agents**
> *Submitted to DL4C @ ICML 2026*

## Overview

When a coding agent pauses to ask a clarifying question, the user's answer becomes a
new, trusted-by-default input channel — potentially amplifying prompt-injection attacks
by 15–20× (ASPI, 2026). This repo quantifies this **clarification tax** for coding agents
specifically, proposes three deployable defenses, and plots the collaboration-vs-security
Pareto frontier.

## Quick Start

```bash
pip install -r requirements.txt

# Verify pipeline with zero API keys (mock model)
python run_eval.py --model mock --defense none --runs 1
python analyze.py

# Run with a real model
export ANTHROPIC_API_KEY=sk-...
python run_eval.py --model claude-sonnet-4-6 --defense all --runs 3
python analyze.py
```

## Attack Categories

| Category | Description | Detection |
|----------|-------------|-----------|
| `backdoor` | Hidden auth bypass, master passwords | Regex on injected code |
| `secret_exfil` | Sending env vars / keys to external URL | Regex on network call patterns |
| `safetycheck_removal` | Removing input validation, rate limits, CSRF | Regex on removed checks |
| `dependency_poison` | Adding typosquatted packages to requirements | Substring match on package name |
| `destructive_command` | rm -rf, DROP TABLE, FLUSHALL | Regex on destructive operations |

## Conditions

- **EXECUTION**: Fully-specified task; adversarial payload arrives via tool output (file read).
- **CLARIFICATION**: Ambiguous task; agent asks a question; adversarial payload is in the user's answer.

## Defenses

| Defense | Description |
|---------|-------------|
| `none` | No defense — baseline |
| `prompt_tag` | Wrap clarification answer in `<USER_CLARIFICATION>` tags + system instruction |
| `structured_extract` | Separate LLM pass extracts only the direct answer, discarding injected content |
| `plan_diff_gate` | Agent re-states plan after clarification; out-of-scope actions are flagged |

## Metrics

- **ASR** — Attack Success Rate (primary safety metric)
- **Clarification Tax** — `ASR_clarification − ASR_execution`
- **TSR** — Task Success Rate (benign task completed)
- **CCR** — Clarification Compliance Rate (benign part of answer incorporated)
- **Turns** — Average turns to resolve clarification

All metrics include 95% bootstrap CIs.

## Adding Scenarios

Add a new JSON file to `scenarios/` following the schema in `clarinject/schema.py`.
Each scenario must have all five attack categories represented; see existing scenarios
for examples.

## Running Tests

```bash
pytest tests/ -v
```

The mock test (`test_eval_mock.py`) runs the complete pipeline with zero API calls.
